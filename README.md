# Needs You

A Mac app (Dock and menu bar) that lets agents ask you something out loud. It speaks the question, opens the mic, waits for your spoken answer, transcribes it and hands the text back to the agent. All speech runs on the Mac: no audio or text goes to a cloud service. It asks once; if nobody answers (30 s), the question is kept as a voicemail that Needs You reads out when he is back. While do not disturb is on, agents get "voicemail" back at once and nothing is spoken.

## For agents

```bash
needs-you ask "The staging deploy is green. Shall I promote it to production?" \
  --title "Promote to production?" \
  --context ./tmp/promote-notes.md      # file or text: shown in the app and kept with the voicemail
  # --project my-site                  # project label (default: the folder you run it in)
```

It waits its turn if another conversation is running, then prints one JSON line:

```json
{"status":"answered","conversation_id":"20261123-174838-181a","transcript":"Yes, go ahead.","turns":[...]}
{"status":"voicemail","conversation_id":"...","state":"The user did not answer, left as a voicemail. ...","turns":[...]}
```

Exit code 0 when answered (or interrupted), 2 when it went to voicemail (or `--once` got no answer: `no_answer`), 1 on error.

Do not disturb: while it is on, `ask`, `say` and `done "<words>"` return at once with `{"status":"voicemail",...}` (exit 2 for ask and say). Nothing is spoken, no sound plays, the mic stays closed. The text is kept as a voicemail with the time, the folder you ran it in and your herdr pane; when the user answers it later, their answer is typed into your chat (ending in the usual voice line). Go on with other work and do not ask again.

You can cut Needs You off by saying "Stop, Claude" while it speaks. The voice stops, a short sound plays, and it listens to what you have to say. You get:

```json
{"status":"interrupted","spoken_until":"The deploy failed on the migration step, and","transcript":"I know, skip it and retry.","turns":[...]}
```

`spoken_until` is roughly what he heard before he stopped it. The conversation stays open: answer with `say`.

Escape stops the voice too (HM-1353), at once, from any app. Needs You only takes the Escape key while its voice plays (a Carbon hot key, no Accessibility permission), so Escape works as usual everywhere else. Escape means quiet: nothing listens afterwards and an open conversation ends. The agent gets `"status":"interrupted"` with `spoken_until`, an empty `transcript` and a `state` saying he pressed Escape. During voicemails Escape keeps the rest for later; during "Which chat?" it cancels.

`transcript` is cleaned up by default (fillers like "uh" and "um", stutters and repeats removed; nothing reworded). `transcript_verbatim` has the exact words when they differ. Settings → Microphones → Transcript switches between Verbatim, Remove Fillers and Polish.

Follow-ups stay in the same conversation:

```bash
needs-you say "Done. Anything else before I merge?"   # speaks, listens, prints the next transcript
needs-you say "Merging now." --no-listen             # speaks only; with no open conversation it speaks on its own, in turn
needs-you done "Thanks, bye."                        # optional last words, then ends it
```

Keep looping with `say` while he keeps talking; call `done` when he says he is done or `say` returns `no_answer`. An answered conversation closes by itself after 3 minutes without a `say`. `--id <conversation_id>` pins `say`/`done` to a conversation. `needs-you status` shows what the app is doing.

Rules:

- Keep `ask` text to one or two spoken sentences. Put commands, links and long detail in `--context`.
- Never put secrets in the text or the context.
- `ask` can block for minutes (queue, a 30 s wait). Run it with a long timeout (Bash `timeout: 600000`).

## Hey Claude (talk into any chat)

Reach by voice (HM-1364): Settings → Agents → Reach by Voice connects Claude Code (`claude mcp add --scope user needs-you -- needs-you mcp`) and Codex (a marked block at the end of `~/.codex/config.toml`, backup `config.toml.needs-you-backup`). `needs-you mcp` is an MCP server on stdio: it registers the agent's chat with the app (agent process, folder, session id, the herdr or tmux pane from its own environment) and keeps it registered with a heartbeat every 30 s; tools `status` (one line on what the chat works on), `ask`, `say`, `done` (same as the CLI) and `inbox`. `needs-you chats` prints the registered chats. A chat goes away when its agent process ends.

Connecting also adds hooks (`needs-you hook <event> --agent claude|codex`, found again by that command; a backup `<file>.needs-you-backup` is kept): Claude Code `~/.claude/settings.json` SessionStart, UserPromptSubmit, PostToolUse, Stop, Notification, SessionEnd; Codex `~/.codex/hooks.json` SessionStart, UserPromptSubmit, Stop. They tell the app the chat's state and recent prompts, and hand over voice messages that waited for the chat: on Stop as `{"decision":"block","reason":…}` (the agent continues with it), on UserPromptSubmit and PostToolUse as `additionalContext`. MCP tool results also carry them. Nothing is typed into a terminal.

Once any chat is connected, "Hey Claude, <chat>: …" goes only to connected chats: the message waits in that chat's inbox and the island says "Queued for <chat>"; the chat gets it on its next tool call, turn end or prompt. "This one" means the connected chat he typed into or talked to last. Voicemail answers go to the connected chat in that pane or folder the same way. Until an agent is connected, the old herdr path (typing into the pane) still works; new chats still open through herdr.

Turn on "Listen for Hey Claude" in the menu bar or Settings. Then say:

(The wake phrase can be changed in Settings → Hey Claude → Wake phrase, e.g. "Hey Baby"; below it is written as "Hey Claude".)

- "Hey Claude, this one: run the tests again" -> the chat in front (the focused herdr agent pane, or the Claude app when it is in front)
- "Hey Claude, trip planner: book the hotel for Friday" -> the chat whose title (or folder, or herdr tab label) matches
  Matching (HM-1364, `Sources/NeedsYouShared/ChatMatcher.swift`): the herdr tab label counts most (1.0), then the folder (0.85, not for chats in the home folder), then the agent's title (0.7; Claude Code sets it from the first prompt and never updates it). Tab labels that say nothing are ignored: digits only, "voice", "continue" and the like, and any label two chats share ("voice: website" counts as "website"). A named chat is sent even if focus moves during the countdown; only "this one" and commands without a name need the chat to stay in front. When the words before a colon match no chat and no project folder ("Hey Claude, two questions: ..."), the whole sentence goes to the chat in front (`ChatMatcher.unmatchedName`, set it to `.ask` to ask instead). Every routing decision (heard name, top 3 with score and field, why) goes to the history entry (`route`) and to `audio.log` (`route: ...`).
- "Hey Claude, deploy it" (no name) -> the chat in front
- "Hey Claude, new chat in website: look at the failing deploy" -> a new herdr tab in the closest folder under ~/Projects, running `claude`, with the message typed in. It asks out loud when the folder is unclear. With no folder named, or when no chat is open or matches, the new chat starts in your home folder. It says where it went.

Wake phrase: Settings → Hey Claude → Wake phrase (default "Hey Claude"). Type a phrase and press Return or Use. The field warns while you type when a phrase is very short (under 2 words and 3 syllables), has a 1-2 letter last word, is long, or is common talk ("hey you", "thank you", "hey Siri"). Test listens for 20 s and shows what was heard and whether it matches; a wake during the test only chimes, nothing is sent. "Hey Claude" keeps its hand-tuned patterns (measured on his clips). Any other phrase gets a matcher built from its words (`Sources/NeedsYouShared/WakeMatcher.swift`): case, accents and punctuation ignored; greetings swapped freely (hey/hay/hi/okay, and "Pay"/"They"/"A" at a sentence start); each word compared by a small phonetic key plus edit distance and syllable count ("Bobby" counts for "Baby", "maybe" and "Bob" do not); one mishearing allowed in the last word; two words heard as one ("Heybaby") count. The early wake on a partial uses the phrase with the first 2-3 letters of its last word ("Hey Ba…", last word of 4+ letters, his voice learned). The phrase and its name are given to SpeechAnalyzer as contextual strings and to Whisper as its prompt. "Stop, Claude" always cuts Needs You off; with another phrase "Stop, <name>" does too. Training and Learn My Voice lines use the phrase; Evaluate scores each clip against the phrase read in it. Unit tests: `swift test`.

Your turn shortcut (HM-1354, default ⌥⇧Space; Settings → Hey Claude → Your Turn Shortcut to change or clear it): the same as saying the wake phrase, without the wake word or the own-voice check. The ears, the chime and listening start at once; it works even when "Listen for Hey Claude" is off (the mic opens for that one command). Press it again while talking to finish, like "done". While Needs You talks it cuts it off like "Stop, Claude" and listens to him (in an ask that is his answer). While he answers an ask it ends the answer. During do not disturb it does nothing but show a moon on the island. ⌥Space is taken by the ChatGPT launcher on this Mac and ⌃⌥Space by the input source switch, hence ⌥⇧Space; Settings shows when another app holds the chosen shortcut. Silent test hooks: `needs-you voice-test --title keys` (registration and what a press would do now), `--title keys:turn` (runs the press handler), `--title keys:escape`.

Do not disturb (HM-1352): "Hey Claude, good night", "Hey Claude, I'm going to take a shower", "do not disturb" or "be right back" turns it on (menu bar and Settings → Do Not Disturb have the switch; the menu bar icon turns into a moon). It has no timer and stays on across restarts (`dnd.json`). While it is on, no agent can speak, play a sound or open the mic; what they wanted to say is kept in `voicemails.json`. "Hey Claude, I'm back" or "Hey Claude, good morning" turns it off and reads the voicemails in order ("At 2 a.m., from website: ..."). After each one he has 8 s to answer: the answer is typed into that agent's chat (its herdr pane, else the one chat in its folder); "next" or silence goes on, "stop" or "that's all" keeps the rest for later. "Hey Claude, what did you work on last night?" speaks a summary per chat; "Good morning, what did you work on last night?" does both. "Play my voicemails" / "any messages?" reads the unheard ones. Only short commands count, from their first words: "this one: write a good night message" still goes to the chat. Silent test hooks: `needs-you wake-test --transcript "Hey Claude, good night"` (prints `presence: ...`), `needs-you voice-test --title dnd|dnd:on|dnd:night|dnd:off-silent|dnd:spoken|dnd:summary|dnd:selftest` (selftest: muted ask and say through the real path, no audio, cleans up), `needs-you voice-test <id>... --title dnd:forget`.

Every message typed into a chat ends with a last line `(sent by voice: reply by voice with needs-you)`, so the agent knows to answer out loud. The line is not spoken and not shown on the island; the history shows it.

Until the wake word, speech is recognized on the Mac with Apple's SpeechAnalyzer (macOS 26+, works without Siri or Dictation). It runs in fast-results mode (`wakeFastResults`, default on), wakes on a "Hey Cl…" partial once your voice is learned, and re-reads with the second recognizer back to back for 2 s after any "Hey": on his 35 wake clips (24 Nov) the chime came a median 0.6 s after the phrase (quiet 0.6, music 0.5, game 1.3) instead of 1.7-2.0 s, same catch rate (29/35), no false wakes on 61 clips without the wake word. The command after "Hey Claude" is transcribed on the Mac too (Parakeet). The command ends when he has finished (Smart Turn, see below), after a 4 s pause at most, or on "done". A pause after a thought left open ("I think I like", "when I try to", "and", "um": `TurnText.trailsOff`) gets 2.5 s more (HM-1360), in commands and in answers. If Silero hears nothing for 4 s after the wake (was 2.5 s), the recognizer reads what came after the wake phrase first; words there keep the turn open. If the name is unclear, it asks out loud which chat, offering 2 or 3 titles.

For 2 s before sending, the notch island shows the chat it goes to and a ring that runs out; Esc or saying "cancel" stops it. There is no other popup: the island, the subtitles and the edge glow are the only things Needs You puts on screen (HM-1363), and with Subtitles on Screen off the countdown shows nothing. Right before typing, it re-reads the target: if the chat is gone, was renamed, or (for "this one") focus moved, nothing is sent. Delivery goes through herdr (`herdr agent prompt`: bracketed paste plus Enter, like typing), or for the Claude app, the clipboard (saved and restored) plus Return, which needs Accessibility access. It never types anywhere else, and never sends an empty or filler-only message. Every send shows up in the history.

The listener pauses while Needs You is speaking or listening in an `ask`, so it never hears itself.

Turn-taking: agents never talk over you. While you are saying a Hey Claude command, or one is being sent, asks and replies wait and play after you finish. While Needs You speaks, "Stop, Claude" (or how it is often heard: "Stop Cloud", "Snow cloud"; or a lone "Stop" when the text has no "stop" in it) cuts it off. Two detectors run on the Mac side by side, SpeechAnalyzer (fast mode) and Parakeet re-reading the last 2 s every 250 ms; on a test file both fire within about 0.1 s of the end of the phrase. Both hear the mic through Apple's voice processing (echo cancellation), so Needs You's own voice does not trigger them. If voice processing cannot start, it falls back to a plain mic, then to plain playback; speech always plays. The mic for `ask` retries on a fresh engine (then the default mic) if it fails to start, and an `ask` whose caller is gone stops before asking again.

Noise: the Hey Claude listener opens on Silero VAD (the level of Apple's on-device voice isolation is the fallback), with 2 s of audio kept from before the opening. While it hears speech, SpeechAnalyzer listens for the wake word and Parakeet re-reads the last 4 s every 1.5 s as a second opinion, which catches a far-field "Hey Claude" the first one misses. In a room where a TV or game keeps talking, "done" ends the command. The recognizers get the plain mic signal. Nothing leaves the Mac.

Speech to text: Whisper large-v3-turbo (WhisperKit, Neural Engine, with a short prompt) for his words and the wake check; Parakeet v2 only for the quick "done" checks. On his clips with game audio mixed in, Whisper caught "Hey Claude" 18/19 (game at the same level) and 15/19 (game 6 dB louder) vs Parakeet 10/19 and 11/19, with no false wakes on 31 clips without the wake word.

Languages (HM-1351, HM-1362): Settings → Microphones → Languages I Usually Speak (English, Turkish, German, French, Italian, Russian; default English) and Only These Languages (off by default). With it off, Whisper scores every one of its languages for each utterance, the picked ones weighted 4×, and follows a language he did not pick once it is clear: at least 1.5 s of his words, top probability ≥ 0.8 and 0.6 ahead of the second, and ≥ 0.9 on its own for an unpicked language (`LanguagePick` in `Sources/NeedsYouShared/TurnText.swift`). Live subtitles wait until the language is clear (Parakeet, English only, used to show Turkish as English-looking gibberish for the first seconds); after 5 s of speech without a clear answer the best of his languages is used. Only These Languages on is the old behaviour below. Test hook: `needs-you stt-test <audio> --title langpick:wturbo@en/tr` (the subtitle decision; a final `!` = only these). With one language Whisper is forced to it (English only is the old path, unchanged). With several, each utterance goes through Whisper's encoder once: the first decoder step is scored over only the chosen languages, the most likely one wins, and the transcript is decoded from the same encoder output in that language, so detection costs one decoder step: on his 165 eval clips (24 Nov) the median went from 487-491 ms to 495-496 ms, CPU 23 % and RAM unchanged, 164/165 English clips detected as English (one wake clip in game noise as Turkish), WER within the run-to-run spread (English only 49-59 % over 4 runs, English + Turkish 52-56 % over 3), wake 29/35 at a median 0.64-0.73 s in both settings. WhisperKit's own detection inside `transcribe` picked English for clear Turkish speech, so it is not used. Transcripts stay in the language spoken (never translated; Polish keeps the language too). The wake check, "Stop, Claude" and Learn My Voice stay English. Parakeet v2 (the quick "done" checks and live subtitles) knows only English: with other languages on, the check about 3 s into a command (or the first pause with 2.5 s of an answer) finds the language with Whisper; English then stays on Parakeet, any other language is read by Whisper (end-word checks every 1.5 s, subtitles every 2 s). End words per language count only when they stand alone at the end ("…, bitti." / "Tamam." / "fertig" / "c'est tout" / "ho finito" / "готово"), because Turkish and German end sentences on the verb ("Test bitti." is a sentence); a lone "Tamam." is kept as the answer. Needs You still speaks with Kokoro's English voices. Test hooks: `needs-you stt-test <audio> --title wturbo+p@en,tr` (prints `lang=`), `--title langid:wturbo[@en,tr]` (language probabilities), `voice-test --title train-eval:wturbo+p@en/tr`.

Speaking other languages (HM-1368): each sentence of what an agent says is spoken in the language it is written in, so a reply that mixes English, Turkish and German switches voice mid-way. Apple's NaturalLanguage picks the language per sentence among English, Turkish, German, French, Italian and Russian; short or unclear sentences ("Okay.", "Danke!") take the language of the sentence next to them, and English needs the least evidence (on the 203 agent messages in his history, 202 stayed English; the one Turkish-and-German test message split correctly). English stays with Kokoro. The other languages use Supertonic-3 (FluidAudio, CoreML on the Neural Engine, 31 languages, 10 speakers): one model of 162 MB (`~/.cache/fluidaudio/Models/supertonic-3`), downloaded the first time a sentence in that language comes up or with Download in Settings → Voice → Other Languages, where each language shows its speaker (Female 2 by default), a preview, and Delete. Deleting a language keeps it on macOS's voice and stops it from downloading again; deleting the last one removes the model. Until the model is there, or if it fails, macOS voices speak (Yelda for Turkish, Anna for German, Thomas, Alice, Milena). Your name can get its own spelling per language so each voice says it right (the `userNameSpellings` pref, e.g. {"de": "…", "de.system": "…" for the macOS voice, "ru": "…"}). Measured 25 Nov on the M5 Pro, warm: 0.05 s for a short line, 0.09-0.11 s for two sentences, an English-Turkish-German-English reply 0.29 s; first use in a fresh process 0.2 s, and about 5 s once right after the download while CoreML compiles. Compared before picking (same lines, Whisper read-back, all local): Piper medium voices through sherpa-onnx (0.03-0.06 s / 0.1-0.18 s, 63 MB per voice plus a 30 MB ONNX runtime and GPL espeak-ng; older VITS voices at 22 kHz), OmniVoice (MLX, 1.5 GB, 0.35-0.8 s, a new random speaker each time), Chatterbox Multilingual (2.2-3 GB, 1-2.7 s, needs a reference voice) and macOS Yelda/Anna (0.6-1.3 s, the old compact voices). Supertonic-3 was as fast as Piper, already in FluidAudio, one download for all languages, and read back cleanly. Test hooks: `needs-you tts-test "<text>" --tts-out <file>` prints `engines` (`["en=kokoro(af_heart) 2.23s","tr=supertonic3(F2) 2.21s","de=supertonic3(F2) 2.72s",…]`), `--title fallback` uses the macOS voices; `NeedsYou --tts-test "<text>" --tts-out <file> [--download tr,de] [--wait-download] [--repeat n]` does the same in its own process without the app (nothing plays), and `NEEDS_YOU_VOICES_DIR=<dir>` keeps its model somewhere else.

Your voice: Settings → Hey Claude → Learn My Voice reads six short lines; repeat each after the beep (about a minute). After that a "Hey Claude" counts only in your voice (CAM++ speaker embeddings from FluidAudio, 3 s windows), your turn ends when only other voices are left (two checks in a row that hear real speech, not his, and never in the first 3 s after the wake; silence never counts as another voice), and stretches without your voice are dropped before transcription. Game voices, a TV and other people are ignored. The voiceprint is one vector in `~/Library/Application Support/Needs You/voiceprint.json`; Forget My Voice deletes it. `voiceThreshold` (default 0.45) tunes how close a match must be.

Training (menu bar → Training…): records up to 30 minutes of your voice while music, a game or a video plays, from the Mac mic and, when the iPhone is near and unlocked, its Continuity mic too. It shows lines to read (wake phrases, commands, your name, free talk, quiet stretches), with level meters, pause/resume, and a session list with delete. Learn From Recordings re-learns the voiceprint from every session, picks the own-voice threshold (at most 2 % of background windows pass) and cuts a test set; Undo puts the previous voice back. Evaluate scores the chosen speech models on that test set per mic (Mac, iPhone, merged): wake catch, false wakes, WER, median time, CPU and RAM. Recordings live in `~/Library/Application Support/Needs You/training/`; per-clip results in `training/eval/details-<model>.json`.

Models (Settings → Models): speech to text and wake check (Whisper large-v3-turbo, Whisper large-v3, distil-large-v3, Canary 1B v2, Parakeet v3, Parakeet v2, Cohere), speaker check (CAM++ or off). Each downloads the first time it is used; switching needs no restart. Voice extraction (PS4, experimental, off by default) pulls his voice out of the mix before speech to text, on the GPU (about 30-50 ms per second of audio, 0.5-0.8 GB while loaded). Its Core ML files are built by `tools/ps4/export_coreml.py`; see `tools/ps4/README.md`.

Two mics (Settings → Models → Two mics): "Best mic per utterance" keeps the take that sounds most like you. "Merge (experimental)" lines up the Mac and iPhone takes (GCC-PHAT offset, then a robust line fit for clock drift) and combines them with AuxIVA (default), the far mic as a noise reference, or per-band SNR weighting. A merge is used only when the takes line up and it beats the best single take. `./scripts/test-merge.sh` runs the synthetic check (37 ms offset, 100 ppm drift): AuxIVA gains about 15 dB over the Mac mic with plain gains, and about 1-7 dB in an echoey room.

Test hooks: `needs-you wake-test --arm-pane <herdr pane id>` (while armed, every voice command and test goes only to that pane, for 10 min; after that nothing is sent at all, also after a restart, until `--arm-pane none` ends the test; Claude chat panes cannot be armed), `needs-you wake-test <audio.wav> [--dry-run]`, `needs-you wake-test --transcript "<text>" [--send]`, `needs-you wake-test <audio> --projects-root <throwaway folder>` (new-chat tests only open folders there), `needs-you clean-test "<text>" [--title verbatim|removeFillers|polish|speech]` (`speech`: what Needs You would say for an agent line), `needs-you play-sounds`, `needs-you stt-test|tts-test|stop-test|turn-test`, `needs-you voice-test <wav>... --title enroll|score|filter|forget|learn`, `needs-you voice-test <in.wav> <out.wav> --title ps4` (PS4 extraction on a file, also with the switch off), `needs-you voice-test <voice.wav> <game.wav> --title merge-selftest`, `needs-you voice-test <a.wav> <b.wav> <out-prefix> --title merge`, `needs-you voice-test --title train-process|train-restore|train-eval:<model>,<model>`, `needs-you voice-test <wav>... --title wake-latency[:fast|:slow][:cmd]` (plays clips through a fresh wake listener in real time, silently, and reports when the wake fired after the speech; `:cmd` also waits for the command to end and says why).

## Subtitles on screen

While you or Needs You talk, big subtitles show at the bottom centre of the screen with the mouse (about 46 pt on a 27" screen, two lines at most, newest words kept), on a blurred dark backing. Your words are white, with the newest word dimmer while it is still being recognised (Parakeet re-reads the command about every 0.8 s); Needs You's are warm peach and advance sentence by sentence with the playback. A soft colour glow runs along the screen edges at the same time (a Metal shader at the display refresh rate: cool white-blue for him, orange for Needs You, brightest at the bottom, pulsing smoothly with the voice level), fades in on "Hey Claude" and out about 1 s after speech ends. It never takes clicks or focus. When nobody talks the overlay is ordered out and its animations removed. Settings → Voice → Subtitles on Screen turns it off. Test hooks: `needs-you voice-test --title overlay-demo` (sample text for both sides, no audio), or `"Needs You.app/Contents/MacOS/NeedsYou" --overlay-demo [--idle-after <s>]` (runs next to the installed app; stays hidden afterwards to measure the idle cost).

## Status island

What Needs You is doing shows in a black island at the top of the screen with the mouse, not in a corner panel. On a MacBook screen it grows out of the notch (the notch size is read from the screen); on other screens it is a pill 6 pt under the menu bar. Settings → Voice → Island style: Automatic (notch where there is one), MacBook notch, External monitor.

States: wake heard (two small "ears" beside the camera), listening (timer, "Say done when you're finished", live mic bars), thinking (dots, up to 15 s while the agent works), sending (the chat name and a ring that runs out over the 2 s in which "cancel" or Esc stops a voice command; HM-1363), Claude speaking (orange, chat name, the sentence being spoken, bars from the voice), done (a check, then it folds back), and errors ("Can't hear you" plus one line on the fix). Sizes grow with a spring (stiffness 380, damping 26) and shrink near critically damped (500, 45); content fades in with a short blur. With Reduce Motion on, sizes change with a plain 220 ms ease-out and the ripple, shake, dots and shimmer stop. It never takes clicks or focus. When idle it is ordered out and has no views that tick: 0.0 % CPU. While expanded it costs about 10 % of one core (release build, 24 Nov). The island is the only status surface: no corner panel, HUD or notification banner; `swift test` (SurfaceGuardTests) fails if code creates another floating panel or posts a notification.

Test hook: `"Needs You.app/Contents/MacOS/NeedsYou" --island-demo [--island-style automatic|notch|external] [--idle-after <s>]` steps through every state with fake levels and no audio, next to the installed app; the style flag is not saved.

## The app

Native macOS layout (HM-1356), built from Apple's HIG pages for settings, the menu bar and sidebars:

- Main window (Dock icon, Window → Needs You ⌘0, or Open Needs You in the menu bar): a sidebar with Conversations, Voicemails (unheard count) and the ten chats or projects heard from most recently; a list grouped by day; the selected conversation or voicemail. Search in the toolbar. Voicemails can be played one by one, answered by typing (the answer goes to that chat), marked heard or deleted. The bottom of the sidebar says what Needs You is doing.
- Settings (⌘,): a toolbar of panes, General, Hey Claude, Voice, Microphones, Models, Do Not Disturb and Agents. The last pane opens again next time. UserDefaults keys are unchanged.
- Dock: Settings → General → Show in Dock (on by default) switches between a normal app (Dock icon, File/Edit/View/Window/Help menus, a Dock menu with Do Not Disturb, Play Voicemails and Listen) and a menu bar only app. Show in Menu Bar hides the menu bar item. One of the two always stays on.
- Menu bar menu: the status line ("Listening for "Hey Claude"", "Do Not Disturb since 21:27", "Speaking to website"), Do Not Disturb, Voicemails (n) (click one to play it), Recent Conversations (last 5), Listen for the wake phrase, Microphone (inputs plus the iPhone mic), Open Needs You ⌘O, Settings… ⌘,, Quit ⌘Q. Training moved to Window → Training (⌥⌘T) and Settings → Models.
- Agent instructions (HM-1355): on launch the app writes `~/.claude/needs-you.md` and keeps one import line `@needs-you.md` in `~/.claude/CLAUDE.md`, between `<!-- needs-you:begin -->` and `<!-- needs-you:end -->` (Claude Code expands `@path` imports relative to the file, without asking for user-level files). The text ships in `Sources/NeedsYouShared/AgentInstructions.swift`; bump `version` when it changes. If the user edited the file, the app keeps their version, writes the new default to `needs-you.default.md` and Settings → Agents offers Show Diff, Keep Mine and Use New Default. Edit… opens the file. The old hand-written "## Needs You: ask … out loud" section in CLAUDE.md is only removed after Review and Remove… and a click. The first change keeps a copy as `CLAUDE.md.needs-you-backup`. `NEEDS_YOU_CLAUDE_DIR=<dir>` points all of this at a test folder.
- Permission prompts by voice (HM-1369, off by default): Settings → Agents → Approve Permission Prompts by Voice shows the hook entry and, after Add Hook, puts it into `~/.claude/settings.json` under `hooks.PermissionRequest` (matcher `Bash|mcp__.*`, timeout 60 s, command `'<app>/Contents/Helpers/needs-you' permission-hook # needs-you:permission-voice`). The file is copied to `settings.json.needs-you-backup` before every change, the rest of it keeps its order and formatting, and turning the switch off removes only that entry. Claude Code runs the hook just before it shows a permission prompt. `PermissionGuard` (`Sources/NeedsYouShared/PermissionGuard.swift`) picks the calls worth asking about: git push (force, delete), hard resets and git clean, `rm -r`/`rm -rf`, deploys (Vercel, Fly, Wrangler, Kubernetes, Terraform, deploy URLs, workflow runs), publishing (npm, Docker, GitHub releases), database writes (SQL writes through psql/mysql/sqlite3, Redis, Prisma), installs (brew, global npm, pip, cargo, `curl | sh`), sudo, ssh/scp, secrets (Infisical, 1Password, GitHub secrets) and risky MCP tools (delete, deploy, merge, send...). For those Needs You asks once, out loud: "website wants to force-push to main. Allow?", waits 12 s for an answer, and says "Okay." / "Okay, I'll say no." Yes, okay, go ahead: allow. No, don't, stop, cancel: deny (Claude is told the user said no). "Always": allow and add Claude Code's suggested allow rule for the project. Anything else (every other call, Do Not Disturb, another conversation running, no answer, an unclear or long answer, the app not running, 50 s gone) prints nothing, so the normal prompt shows; it never allows on its own. Each asked call adds one line (project, kind, outcome, never the command) to `permission-hook.log`. Silent test hooks: `NEEDS_YOU_HOOK_DRY=1 needs-you permission-hook < input.json` prints what it would ask; `NEEDS_YOU_HOOK_TEST_INPUT=<wav>` or `NEEDS_YOU_HOOK_TEST_SILENCE=1` go through the running app muted (no sound, no mic, removed from the history); `scripts/test-permission-hook.sh` runs both against the installed app.
- Sounds (HM-1348): the default set, Rosewood, is soft marimba and a log drum in a small room, bundled as 44.1 kHz mono WAV in `Resources/Sounds/Rosewood/` (one file per cue, including Do Not Disturb on and off) and copied into the app by `scripts/bundle.sh`. All cues load into memory at launch, so the wake chime only schedules a ready buffer. Settings → Voice → Sounds switches to Classic (the old synthesized cues). The sounds are made from CC0 recordings in the Versilian Community Sample Library (VCSL) with `tools/sounds/build_rosewood.py`; the sources are listed in [ACKNOWLEDGEMENTS.md](ACKNOWLEDGEMENTS.md).
- App icon: Resources/AppIcon/ (AppIcon.icns, AppIcon-1024.png, Icon Composer AppIcon.icon; regenerate with render.py). `scripts/install.sh` compiles the .icon with actool and falls back to the .icns.
- SwiftPM writes SDK 14.0 into the binaries, which keeps AppKit in the macOS 14 look; `scripts/install.sh` stamps the real SDK version with `vtool` so the app gets the current design.

Test hook: `NeedsYou --ui-demo main|settings|training|menu [--section voicemails] [--select first] [--pane agents] [--sheet diff|legacy] [--size 1180x720]` opens the windows next to the installed app with no socket, mic, hot keys or audio, reads the installed app's settings and files and writes none of them. It prints window numbers for `screencapture -l`.

## Install

```bash
scripts/install.sh
```

Builds, signs with your Apple Development identity (`SIGN_IDENTITY`; a stable signature keeps the microphone grant across rebuilds), installs `~/Applications/Needs You.app`, links `~/.local/bin/needs-you`, and downloads the speech models once (`Needs You --download-models`: Parakeet into `~/Library/Application Support/FluidAudio/Models`, Kokoro into `~/.cache/fluidaudio`, about 630 MB; never committed). `SKIP_MODELS=1` skips that check.

If `swift build` hangs on "Fetching binary artifact" (FluidAudio's NemoTextProcessing xcframework), download it with curl, check the sha256 from FluidAudio's Package.swift, and copy it to `~/Library/Caches/org.swift.swiftpm/artifacts/https___github_com_FluidInference_text_processing_rs_releases_download_v0_3_1_NemoTextProcessing_xcframework_zip`.

The first time it listens, macOS asks for microphone access.

Local builds never update themselves. Release builds download the speech models in the background on first launch.

## Releases

`.github/workflows/release.yml` turns a push to main into a release once the repo variable `RELEASES_ENABLED` is `true`. The version comes from the commit subjects since the last `v*` tag (`scripts/release/next-version.sh`): `feat!:` or `BREAKING CHANGE` bumps major, `feat:` bumps minor, anything else bumps patch, and `[skip release]` skips. The build number is the commit count.

The macOS job runs `scripts/bundle.sh` (the same bundle `install.sh` makes), signs with the Developer ID certificate (`MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`), notarizes and staples with the App Store Connect key (`ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`), then builds a DMG and a zip (`scripts/release/package.sh`). It signs the zip for Sparkle (`SPARKLE_ED_PRIVATE_KEY`) and writes `appcast.xml` (`scripts/release/appcast.sh`). Finally it creates the tag and the GitHub release with the DMG, the zip and the appcast. The app reads `releases/latest/download/appcast.xml`. With `vars.HOMEBREW_TAP` and `HOMEBREW_TAP_TOKEN` set, it also pushes `Casks/needs-you.rb` (`scripts/release/cask.sh`).

A manual run (Actions → Release → Run workflow) is a dry run by default: it builds, signs and notarizes, and keeps the files as a workflow artifact without tagging.

The secrets are GitHub Actions secrets of this repo: `SPARKLE_ED_PRIVATE_KEY`, `MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`.

To test updates on a throwaway copy, build two versions with `BUNDLE_ID=dev.homemade.needs-you.updatetest FEED_URL=http://127.0.0.1:8765/appcast.xml ED_PUBLIC_KEY=… scripts/bundle.sh`, serve the newer zip and its appcast, then run `"<old copy>/Contents/MacOS/NeedsYou" --update-check` (add `--install` to install it when the process exits).

## How it works

- CLI and app talk over a Unix socket in `~/Library/Application Support/Needs You/` (directory 0700, socket 0600, peer uid checked).
- Speech, all local through [FluidAudio](https://github.com/FluidInference/FluidAudio) 0.18.3 on the Neural Engine. Voice: Kokoro 82M (`af_heart` by default, Settings > Voice), with a custom lexicon so your name (Settings → General) and "herdr" are said right; about 0.1 s for a short line, 0.4 s for two sentences once warm. Other languages: Supertonic-3, sentence by sentence (see Speaking other languages above). If a model fails, macOS's own voice for that language speaks. Transcripts: Whisper large-v3-turbo (see Languages above); NVIDIA Parakeet TDT 0.6B v2 (English) for the quick checks, about 50–90 ms per pass, with a small spelling fix-up for your name, herdr and the words in the `transcriptFixes` pref. Both models load on first use and unload after 10 idle minutes: the idle app is about 35 MB, about 300 MB while talking.
- Measured 23 Nov on real recordings (4 clips, 33 words): Parakeet 9 % word error at about 60 ms, Apple SpeechAnalyzer 9 % at 90 ms, ElevenLabs Scribe (old) 6 % at 780 ms. Parakeet sometimes mishears names; "Also Heard As" in Settings → General fixes them. On strongly accented or noisy synthetic speech ElevenLabs was clearly more robust (Parakeet 37 % vs 21 % word error overall). `needs-you stt-test <audio> --title v2|v3|ultra|apple|cohere`, `tts-test`, `stop-test` measure this.
- Listening: Silero VAD (FluidAudio, MIT) decides when he is speaking, from the voice itself rather than the loudness. The wait (30 s) only runs until he starts talking. After a 2 s pause (Settings: "Pause before checking if you're done"), Pipecat Smart Turn v3.2 (BSD-2, CoreML port, 17 MB) judges from his voice whether he has finished; if not, the turn ends after 4 s of pause at most ("Longest pause in your turn"). The defaults are 2 s / 4 s because 0.75 s cut people off when they paused on purpose. Also on "done" / "that's it" / "over", the Stop button, or after 2 minutes. Measured on his reading clips (23 Nov) with a 0.75 s check: the turn ended about 0.8 s after his last word (3 s before), with no cut-offs on his "uh" pauses. Parakeet's own end-of-utterance model heard nothing in most of his recordings and was dropped. If Silero cannot load, the old level gate takes over. A filler-only turn ("ähm", "uh", "hmm") is not an answer: it keeps listening. A sound plays when listening starts and when it stops; nothing plays in between. Audio is 16 kHz mono WAV in a private temp folder, deleted after transcription.
- Spoken text (HM-1370): right before speech, every line (ask, say, done, voicemails, summaries) goes through `SpeechText` (`Sources/NeedsYouShared/SpeechText.swift`). Paths become their last part ("Sources/NeedsYou/Sounds.swift" is said "Sounds dot swift"), URLs their domain ("github dot com"), code fences "a code block"; backticks, markdown (headings, emphasis, quotes, bullets, tables), emoji, git SHAs, UUIDs and long ids are dropped; dashes become pauses ("3–5" is "3 to 5"); "v1.2.3" is "version 1.2.3"; "~50 ms", "630 MB", "23 %", "→", "≥" are read as words. Subtitles and history keep the original text. Tests: `SpeechTextTests` (real lines from history.json must come out unchanged).
- History (last 200 requests) is in `history.json` next to the socket. Settings: voice, volume, wait time, microphone, open at login.

Test flags (not for agents): `--mute`, `--tts-out <file>`, `--input-file <audio>`, `--simulate-silence`, `--wait <seconds>`, `--vad-file <audio>` (plays a file through the real listening path in real time).
